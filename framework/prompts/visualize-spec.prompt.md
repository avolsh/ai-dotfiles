#skill:writing-specs
Visualize sub-step inside Specify — spec stays at `status: specify` throughout. Populate `## Design` with Mermaid (structure/flow/schema) and/or Figma frames (UI surfaces), then hand back to [`create-spec.prompt.md`](create-spec.prompt.md) for the requirements gate. Lifecycle: [`spec-lifecycle.md`](../spec-workflows/spec-lifecycle.md).

## Preconditions
- Spec at `status: specify` with `## Requirements` + `## Acceptance Criteria` drafted, and a trigger from [`spec-lifecycle.md § Visualize sub-step`](../spec-workflows/spec-lifecycle.md#visualize-triggers) applies. No trigger → write `Skipped — <reason>` under `## Design` and do not run this prompt.

## Steps
1. **Load context** — the spec, project `docs/architecture/` (system overview, module map, the `design-system.md` Figma version table), reference schemas in `affected-docs`.
2. **Confirm the Figma file** — before the first Figma read, ask the human: continue with the key declared in the project's version table, or adopt a new one (a copy of the current design, cut for this milestone)? Default: continue. Ask on **every** run — only the human knows a milestone was cut. A supplied key is written into the version table (predecessor → `frozen`) **before any further Figma call**, and is the only key used for the rest of the run. Skip only when the project declares no key yet. See [`references/figma-file-organization.md § 6`](references/figma-file-organization.md).
3. **Choose the medium** — minimum set; ≤30 nodes per diagram. Pipeline / data flow → `flowchart` LR; multi-service async → `sequenceDiagram`; schema / entity → `erDiagram` or `classDiagram`; entity state machine → `stateDiagram-v2`. **UI surface (screen / view / component) → Figma, not Mermaid:** embed each frame as a link-wrapped image (see § Hard rules); use a `flowchart` with subgraphs only for navigation/composition, never for visual design. Before creating any Figma frame, run the **design-system-first** rule (see § Hard rules).
4. **Write `## Design`** — replace placeholder. Precede each diagram or Figma frame with a one-sentence caption: *what it shows and from whose perspective*. Every Figma caption MUST record the design-system source: `(design-system: <library-file-key>)` or `(design-system: none — new library built: <key>)`. Use Before/After pairs when the spec changes existing flow.
5. **Re-run the Split check** — the affected code is loaded by now, so the file surface the check reasons about is knowable for the first time; re-run [`authoring-steps.md § B`](../skills/writing-specs/references/authoring-steps.md) against it and record the verdict under `## Split Decision`, dated, whether or not it changed. The incremental cost is a file count; a verdict that flipped to `split-recommended` is surfaced at the requirements gate as a decision for the human, never acted on here.
6. **Update + hand back** — keep `status: specify`, update `*Last updated:*` (if diagrams reveal new requirements or scope conflicts, return to Specify and revise FRs/ACs first). Then post a short summary (diagram types used, key design decisions, the step 5 re-check verdict) and return control to [`create-spec.prompt.md`](create-spec.prompt.md) for the requirements gate.

## Hard rules
- Status stays at `specify` (Visualize is a sub-step, not a status — see [`spec-lifecycle.md § Rules #8`](../spec-workflows/spec-lifecycle.md#visualize-not-a-status)). Diagrams and Figma frames MUST match approved requirements, not aspiration. One-line captions only — never paraphrase the diagram or frame in prose. No `## Tasks` table here — see [`spec-lifecycle.md § Rules #2`](../spec-workflows/spec-lifecycle.md#never-tasks-table-at-specify).
- **Design-system-first (Figma).** Before creating any frame: (1) discover the existing design system — call `get_libraries` + `search_design_system` first; call `get_variable_defs` only once you have a concrete reference node. (2) Reuse the discovered variables, components, and text styles — MUST NOT hardcode values or duplicate shared primitives. (3) If a required primitive is absent, build it as a design-system library via `figma-generate-library` / working-with-design-systems skills before creating frames. (4) **Build by instancing, not copying:** repeated pills/cards are instances of one component, new components/sections use auto-layout for spacing (never hand-computed `x`/`y`), and a frame grown taller MUST grow its host Section without overlapping the next — see [`references/figma-file-organization.md § 5 Build mechanics`](references/figma-file-organization.md). Hardcoded styles or ad-hoc components not in the library MUST be fixed before handing back.
- **The current file carries no divergence (Figma).** Before drawing a proposed state, check the frame you are cloning against what the product does **today**. A base frame that contradicts today's product — a deleted configuration key, a renamed unit, a removed field — is corrected **in this run**, as a separate act from drawing the proposal: the base frame gets today's truth, the proposal gets its own `· <state>` frames, and an unapproved proposal is never written into the base frame. At closure the base frame gets what landed. Archived specs resolve against **frozen** keys, so their links never constrain the current file — that argument is the versioning scheme read backwards. See [`references/figma-file-organization.md § 6`](references/figma-file-organization.md).
- **Screenshot embeds (Figma).** Every frame under `## Design` is a **link-wrapped image** — `[![[W-12] Invoice — List](https://www.figma.com/api/mcp/asset/<uuid>)](https://www.figma.com/design/<fileKey>?node-id=<node-id>)` — with the frame's `[<ID>] <Entity> — <View> · <state>` name as alt text, so an expired URL still renders as a named, clickable reference. Screenshot files MUST NOT be committed to any repository or uploaded to external storage; the outer node URL carries everything `get_screenshot` needs to rebuild the image. **Regenerate before the gate:** on handing the spec back for the requirements gate, and whenever a spec with dead images is re-opened, re-run `get_screenshot` for every node URL under `## Design` and replace the image URLs in place. Format, rationale, and the versioning/freeze procedure: [`references/figma-file-organization.md § 6`](references/figma-file-organization.md).
- **File organization (Figma).** Pages, design-system structure, and component/variable/frame naming MUST follow [`references/figma-file-organization.md`](references/figma-file-organization.md): numbered + Title Case pages with **platform as the primary axis** (`10 Web`/`20 iOS`/…) and **domains as Sections** (no empty platform pages), ≤ ~9 top-level pages, Foundations/Components on their own pages (variables/styles, never hardcoded), slash-named components with variant properties, token-path variables, and every root frame named `[<ID>] <Entity> — <View> · <state>` (ID tag required, size never in the name). Never park content off-canvas to avoid creating a page.
