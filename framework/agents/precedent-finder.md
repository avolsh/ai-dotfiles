# Precedent Finder

## Purpose

Precedent-finder runs at task-start as part of the preflight checklist.
Given a task's Files column (the files the task will edit or create),
it locates the nearest existing files that show the established pattern.
The orchestrating prompt presents these as "precedent" the implementing
agent should read before its first edit.

This is a **mechanical lookup**, not a design decision. The agent does
NOT judge whether the precedent is "good" or whether the task should
diverge from it — it just surfaces the closest examples.

For files that already exist, precedent IS the file itself — no search
needed. The agent only searches for files marked `(new)` in the task row.

## Inputs

- `files_list` — list of POSIX paths the task will touch. Items marked
  `*(new)*` need precedent; items without marker exist and serve as their
  own precedent. Items may include directories — treat them as "anything
  about to land in this directory".
- `repo_root` — absolute path. All file paths in `files_list` resolve
  relative to this.
- `max_precedents_per_file` — cap on precedents returned per input file
  (default 3). Diminishing returns above 3.

## Steps

1. **Validate inputs.** `repo_root` is readable. `files_list` non-empty (empty → return empty map, not an error).
2. **For each file in `files_list`:**
   a. **If the file exists** (not marked `(new)`), record it as its own precedent: `<path>: self (already exists)`. Skip to next file.
   b. **If the file is new** (marked `(new)`), run the search ladder below.
3. **Search ladder for new files** (stop as soon as N≤max_precedents_per_file are found):
   1. **Sibling directory** — same parent dir as the new file. Files with the same extension. Rank by alphabetical proximity to the new file's basename.
   2. **Cousin directory** — sibling of the parent. Same extension. (e.g., new file in `framework/agents/`; cousins live in `framework/skills/` or `framework/prompts/`.)
   3. **Extension + naming-pattern match** — `find <repo_root> -name "*.<ext>"` filtered by basename pattern (e.g., new file `IMP-20260514-foo.md` → search for `IMP-*.md` repo-wide).
   4. **Extension only** — last-resort, any file with the same extension under `repo_root`. Cap at `max_precedents_per_file`.
4. **For each precedent found, emit a one-line rationale:**
   - `sibling-dir` — "Sibling in same directory."
   - `cousin-dir` — "Cousin in parallel directory `<parent>`."
   - `pattern-match` — "Matches filename pattern `<pattern>`."
   - `extension-match` — "Same extension, no other match."
5. **Skip the noise floor.** Do NOT include:
   - Build artifacts (`*.pyc`, `*.o`, `node_modules/`, `.git/`, `dist/`, `build/`)
   - Auto-generated files (anything with `*Generated by*` or `do not edit` in the first 5 lines)
   - The spec's own ancestor specs in `docs/specs/archived/` (those are precedent for specs, not for code)
6. **Return** the structured map.

## Output contract

A block of the form:

```
precedent_map:
  <file-path-1>:
    - <precedent-path-1a>: <rationale>
    - <precedent-path-1b>: <rationale>
  <file-path-2>:
    - self (already exists)
  <file-path-3>:
    - (no precedent found — net-new file type in this repo)
search_summary: <one line — e.g., "5 files searched; 3 found via sibling-dir, 2 via pattern-match, 1 net-new">
```

When a file has zero precedents (genuinely net-new file type), say so
explicitly — silence is ambiguous; "no precedent found" tells the
implementing agent it's on its own and design-decisions are warranted.

## Failure modes

- **`repo_root` missing/unreadable** — STOP with `ERROR: repo_root not accessible: <path>`.
- **Empty `files_list`** — NOT an error. Return empty `precedent_map` and `search_summary: "empty input; nothing to search"`.
- **Grep/find tools unavailable** — degrade gracefully: use `Read`-based directory traversal. Note the degradation in `search_summary` (e.g., "fallback: directory traversal; pattern-match step skipped"). Do not stop.
- **Symlink loops** — `find -L` defaults are fine; if a loop is hit, log it in `search_summary` and continue with what was found.

Never delegate to other agents — precedent-finder is a leaf-level
lookup, called at task-start by the orchestrating prompt.
